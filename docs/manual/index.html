01 / 12요약

logbook은 에이전트가 개발을 맡고, 사람은 정해야 할 것만 정하는 개발 흐름입니다

요청이 들어오면 에이전트가 이슈를 만들고 코드와 자료를 조사합니다. 사용 흐름이 달라지는 선택은 사람에게 묻고, 계획은 슬라이드로 보고해 착수 승인을 받습니다. PR을 연 뒤에는 증거와 별도 리뷰를 담은 결과 보고로 머지를 고르게 합니다.

02 / 12설치

플러그인을 설치하고, 프로젝트마다 /logbook:rulebook을 한 번 실행합니다

  1. claude plugin marketplace add dincal/agent_logbook
claude plugin install logbook@agent-logbook

  2. 세션을 새로 열거나 /reload-plugins를 실행해 명령과 hook을 불러옵니다.

  3. 프로젝트에서 /logbook:rulebook을 실행합니다. 바뀔 파일을 먼저 보여 주고, 승인하면 AGENTS.md 규칙 블록, @AGENTS.md 한 줄짜리 CLAUDE.md, 플랜 저장 위치, 이슈 라벨 5개를 설치합니다.

  4. 이미 개발 중인 프로젝트라면 이어서 /logbook:sync를 실행합니다. 예전 도구의 흔적과 정해진 자리 밖의 문서를 정리하고 프로젝트 문서를 씁니다(07장).

새 버전으로 올리기 
claude plugin marketplace update agent-logbook
claude plugin update logbook@agent-logbook

갱신한 뒤 새 세션을 엽니다. 규칙 블록이 바뀌었으면 프로젝트마다 /logbook:rulebook을 다시 실행합니다.

Codex · 다른 하네스 
codex plugin marketplace add <저장소 로컬 경로>
codex plugin add logbook@agent-logbook

Antigravity와 OpenCode는 skills/ 아래 폴더를 스킬 경로에 링크하고, scripts/rulebook.sh --apply로 AGENTS.md에 규칙을 넣습니다.

private 저장소 마켓플레이스를 추가하는 계정에 이 저장소를 읽을 수 있는 git 인증(SSH 키 등)이 있어야 합니다.

04 / 12명령

명령 다섯 개가 흐름의 각 단계를 맡습니다

/logbook:rulebook
프로젝트당 한 번

작업 규칙을 설치합니다. 다시 실행하면 규칙 블록만 갱신하고, 바뀐 게 없으면 "변경 없음"을 출력합니다. 기존 프로젝트면 /sync를 이어서 실행하라고 알려 줍니다.

결과
AGENTS.md 블록, CLAUDE.md, 라벨, docs/plans/
/logbook:brief
구현 전

조사하고, 흐름이 달라지는 선택은 묻고, 화면이 바뀌면 시안을 승인받습니다. 상세 문서와 브리핑 슬라이드를 만들어 이슈에 링크한 뒤 승인을 기다립니다.

예
/logbook:brief 로그인에 속도 제한 추가 · /logbook:brief #42
/logbook:mission
/goal을 맡길 때

플랜 모드처럼 계획을 승인받고, 화면 시안까지 승인받은 뒤 바로 붙여 넣을 /goal 문장을 냅니다. 구현은 하지 않습니다.

예
/logbook:mission #42
/logbook:debrief
PR 직후

완료 조건마다 증거를 모으고, 프로젝트 문서를 코드와 대조하고, 별도 리뷰어의 검토를 받아 결과 보고를 올립니다. 끝나면 머지·재리뷰·남은 지적 고치기·PR 열어두기 중 권장안을 이유와 함께 제시합니다.

예
/logbook:debrief · /logbook:debrief 57
/logbook:sync
기존 프로젝트 도입, 문서가 뒤처졌을 때

예전 도구의 흔적과 정해진 자리 밖의 문서를 정리하고, 프로젝트 문서(docs/system/)를 코드에서 쓰거나 뒤처진 부분만 다시 씁니다. 규칙 블록이 없으면 멈추고 /rulebook을 먼저 안내합니다.

예
/logbook:sync · /logbook:sync full

리뷰어는 Claude Code에서 Sonnet 모델, medium effort로 돌고, 다른 하네스에서는 세션 모델을 씁니다.

05 / 12브리핑 쓰는 법

브리핑은 상사에게 보고하듯 쓰고, 그림은 억지로 그리지 않습니다

보고 순서

첫 장에서 결론과 요청을 말하고, 배경, 하는 일, 주요 결정, 위험과 판단 필요, 일정과 검증 순서로 이어 갑니다. 주요 결정은 사용자가 정한 것과 에이전트가 정한 것을 나눠 보여 줍니다.

묻는 기준

요청에서 정해지지 않았는데 사용 흐름이 달라지는 부분(어떤 명령이 무엇을 하는지, 어떤 단계를 거치는지, 언제 무엇을 승인하는지, 파일과 데이터가 어떻게 되는지)은 묻습니다. 사소한 것은 묻지 않습니다.

그림 규칙
  • 그림으로 표현할 수 있는 내용은 그림으로 표현합니다. 장마다 그림 수를 정하지는 않습니다.
  • ERD와 흐름도는 억지로 그리지 않습니다. ERD에는 DB 테이블만 넣습니다.
  • 주요 로직의 흐름과 DB 스키마 변화는 반드시 넣습니다.
  • 프로젝트 문서의 ERD에는 DB의 모든 테이블을 넣습니다.
  • md 파일에는 HTML을 넣지 않습니다. 그림은 mermaid로 그리고, 굵은 숫자로 시작하는 목록은 슬라이드에서 타일이 됩니다.
  • AI 모델을 부르는 단계는 그림에 모델 이름과 프롬프트 요지(넣는 것, 요청, 받는 것)를 적고, 표에 설정, 검사, 실패하면 어떻게 되는지를 적습니다.
쉬운 말

독자는 컴퓨터공학 학부를 졸업했지만 이 프로젝트는 모르는 사람입니다. 이 프로젝트나 도구에서만 쓰는 말은 처음 나올 때 풀어 씁니다. 기준은 templates/writing.md에 있고, 모든 명령이 따릅니다.

화면 시안 화면을 새로 만들거나 크게 바꾸면 구현 전에 Claude Code의 /design 캔버스로 시안을 만들어 승인받습니다. 승인본의 사본은 docs/designs/<번호>-<slug>/에 남습니다.
06 / 12프로젝트 문서

지금 시스템의 모습은 문서 네 개에 담고, 핸드북 링크 하나로 봅니다

overview.md

시스템이 하는 일과 쓰는 사람, 시스템 지도, 바꾸기 어려운 선택과 위험, 용어

stack.md

구성 요소와 기술 스택(구성도와 표), 배포와 실행 환경, 개발 도구

flows.md

서비스의 핵심 흐름 3~7개와 흐름도

data-model.md

DB가 있을 때만 둡니다. DB의 모든 테이블이 들어간 ERD와 테이블 설명

  • 문서마다 첫 줄에 그 문서가 설명하는 코드 경로를 적습니다. scripts/system-check.sh는 그 코드가 문서보다 나중에 바뀌었으면 "뒤처짐"으로, ERD의 테이블 수가 스키마와 다르면 경고로 알려 줍니다.
  • 이 문서가 설명하는 내용을 바꾸는 PR은 같은 PR에서 문서도 고칩니다. /debrief가 대조하고, 머지하면 핸드북을 같은 링크에 다시 게시합니다.
  • 핸드북은 scripts/render-system.sh가 문서 네 개를 슬라이드 하나로 묶은 웹 페이지입니다. 링크는 overview.md 머리말에 있습니다.

08 / 12hook

hook 두 개가 흐름을 확실하게 받칩니다

hook은 Claude Code가 특정 순간에 자동으로 실행하는 스크립트입니다.

plan-preview · 플랜 승인 직전과 직후

브리핑 없는 플랜을 되돌리고, 있는 플랜은 브라우저로 엽니다

  • 플랜에 <!-- brief:begin --> 줄이나 끝 줄이 없으면 플랜을 되돌리고 무엇이 빠졌는지 알려 줍니다. 그림이 있는지는 검사하지 않습니다.
  • 블록이 있으면 .logbook/briefs/plan-preview.html을 만들어 엽니다. 승인은 평소처럼 터미널에서 합니다.
  • 승인 직후에는 코드보다 브리핑 게시와 이슈 링크를, 화면이 바뀌면 시안 승인을 먼저 하라고 알립니다.
  • 작은 수정은 플랜에 <!-- brief:skip -->, 브라우저를 열지 않으려면 LOGBOOK_NO_OPEN=1.
debrief-gate · 대화가 끝날 때

PR에 결과 보고가 없으면 한 번 막습니다

  • 현재 브랜치의 열린 PR 본문에 <!-- logbook:debrief -->가 없으면 대화 종료를 막고 /logbook:debrief를 안내합니다.
  • 기본 브랜치, PR 없음, 머지된 PR, gh 오류, 이미 확인한 커밋은 그대로 통과합니다.
  • 연속으로는 한 번만 막습니다.
09 / 12/mission과 /goal

무인 실행은 /logbook:mission으로 계획과 시안을 승인받고 /goal로 맡깁니다

  1. /logbook:mission <목표 또는 #이슈>를 실행합니다. 플랜 모드로 들어가 조사하고, 흐름이 달라지는 선택은 이때 모두 묻습니다. 무인 실행 중에는 물을 수 없기 때문입니다.

  2. 플랜 승인 화면이 뜨면 브라우저의 브리핑을 확인하고 승인합니다.

  3. 화면이 바뀌는 계획이면 시안을 만들어 승인을 받습니다. 플랜 모드에서는 시안을 올릴 수 없어서 승인 뒤에 합니다.

  4. 이슈, 상세 문서, 작업 브랜치, 브리핑 링크가 준비되고 /goal 문장이 코드 블록으로 나옵니다.

  5. 저장소에서 새 세션을 열어 /goal …을 붙여 넣습니다. 이것이 착수 승인입니다.

/goal 이슈 owner/repo#42를 완료한다. 브랜치 feat/42-rate-limit에 있는 docs/plans/42-rate-limit.md의 계획대로 구현하고 PR을 연다.
완료 조건. 항목마다 확인한 명령과 출력을 대화에 그대로 보인다.
1. `pnpm test`가 종료 코드 0이다.
2. PR 본문에 Closes #42, 수용 기준 체크리스트와 증거, 디브리핑 링크, <!-- logbook:debrief -->가 있다.
지킬 것: main에 직접 커밋하지 않는다. 테스트를 약화하지 않는다. docs/system/이 설명하는 내용을 바꾸면 같은 PR에서 문서도 고친다.
매 턴 끝에 남은 조건 번호를 적는다. 40턴 안에 끝나지 않으면 멈추고 보고한다.
  • /goal의 평가 모델은 대화만 읽습니다. 조건마다 명령과 출력을 대화에 남기게 합니다.
  • 목표 문장은 4,000자까지입니다. 자세한 내용은 상세 문서에 두고 문장에는 경로만 적습니다.

자주 막히는 곳은 아홉 가지이고, 대부분 명령 하나로 풀립니다

규칙이 적용되지 않는 것 같습니다작업 폴더 위쪽 어딘가에 다른 CLAUDE.md가 있으면 Claude Code가 AGENTS.md를 읽지 않습니다. 프로젝트에 @AGENTS.md 한 줄짜리 CLAUDE.md가 있는지 확인하고, 없으면 /logbook:rulebook을 다시 실행합니다.
gh 명령이 다른 계정으로 실행됩니다/logbook:rulebook이 gh 계정을 AGENTS.md 트래커 줄에 적습니다. 명령과 hook은 GH_TOKEN="$(gh auth token --user <계정>)"으로 그 계정을 씁니다.
/sync가 멈추고 /rulebook을 먼저 하라고 합니다AGENTS.md에 logbook 규칙 블록이 없는 저장소입니다. /logbook:rulebook을 실행한 뒤 /logbook:sync를 다시 실행합니다.
system-check가 "뒤처짐"을 알립니다문서가 설명하는 코드가 문서보다 나중에 바뀌었습니다. 해당 절을 고치거나 /logbook:sync를 실행합니다. 확인해 보니 고칠 것이 없으면 문서 첫 줄 주석의 checked="날짜"만 고칩니다.
브리핑이나 핸드북 링크를 만들 수 없습니다Artifact는 claude.ai에 로그인하고 Anthropic API로 연결된 세션에서만 게시됩니다. 게시할 수 없으면 .logbook/의 로컬 파일 경로를 링크로 씁니다.
/design 시안을 만들 수 없습니다Claude Code 2.1.265 이상과 claude.ai 로그인이 필요합니다. 쓸 수 없는 환경에서는 docs/designs/에 HTML 시안을 만들어 브라우저로 확인합니다.
플랜을 승인할 때 브라우저가 열리지 않습니다LOGBOOK_NO_OPEN이 설정됐는지, 플랜에 <!-- brief:begin -->가 단독 줄로 있는지 확인합니다. 미리보기 파일은 .logbook/briefs/plan-preview.html입니다.
대화가 끝나지 않고 계속 돌아옵니다열린 PR 본문에 <!-- logbook:debrief -->가 있어야 통과합니다. /logbook:debrief를 실행하거나, 작은 수정이면 증거 목록과 표시만 PR 본문에 넣습니다.
Codex에서 명령이 보이지 않습니다codex plugin list로 설치 상태를 보고 새 세션을 엽니다. hook은 /hooks에서 신뢰 등록해야 실행됩니다.

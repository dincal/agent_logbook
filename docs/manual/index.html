01 / 09요약

logbook은 에이전트가 정하고, 사람은 착수와 머지 두 번만 보는 개발 흐름입니다

요청이 들어오면 에이전트가 이슈를 만들고 코드와 자료를 조사해 스펙을 정합니다. 사람은 구현 전 브리핑과 구현 후 디브리핑만 검토합니다. 요청이 여러 뜻으로 읽히면 구현 전에 되묻습니다.

02 / 09설치

플러그인을 설치하고, 프로젝트마다 /logbook:rulebook을 한 번 실행합니다

  1. claude plugin marketplace add dincal/agent_logbook
claude plugin install logbook@agent-logbook

  2. 세션을 새로 열거나 /reload-plugins를 실행해 스킬과 hook을 불러옵니다.

  3. 프로젝트에서 /logbook:rulebook을 실행합니다. 바뀔 파일을 먼저 보여주고, 승인하면 AGENTS.md 규칙 블록, @AGENTS.md CLAUDE.md, plansDirectory, 이슈 라벨 5개를 설치합니다.

Codex · 기본 지원 
codex plugin marketplace add <저장소 로컬 경로>
codex plugin add logbook@agent-logbook

Claude용 매니페스트를 그대로 읽습니다. 설치 뒤 새 세션을 엽니다.

Antigravity · OpenCode · 안내

skills/ 아래 폴더를 각 하네스의 스킬 경로에 링크하고, scripts/rulebook.sh --apply로 AGENTS.md에 규칙을 넣습니다.

hook과 /goal은 지원하지 않습니다.

private 저장소 마켓플레이스를 추가하는 계정에 이 저장소를 읽을 수 있는 git 인증(SSH 키 등)이 있어야 합니다.

04 / 09스킬

스킬 네 개가 흐름의 각 단계를 맡습니다

/logbook:rulebook
프로젝트당 한 번

작업 규칙을 설치합니다. 다시 실행하면 규칙 블록만 갱신하고, 바뀐 게 없으면 "변경 없음"을 출력합니다.

예
/logbook:rulebook
결과
AGENTS.md 블록, CLAUDE.md, 라벨, docs/plans/
/logbook:brief
구현 전

조사하고, 애매한 점만 묻고, 결정합니다. 상세 문서와 브리핑 HTML을 만들어 이슈에 링크한 뒤 승인을 기다립니다.

예
/logbook:brief 로그인에 속도 제한 추가 · /logbook:brief #42
결과
이슈, docs/plans/<번호>-<slug>.md, 브리핑 링크
/logbook:mission
/goal을 맡길 때

플랜 모드처럼 계획을 승인받은 뒤, 바로 붙여 넣을 /goal 문장을 냅니다. 구현은 하지 않습니다.

예
/logbook:mission #42 · /logbook:mission 결제 모듈 리팩터링
결과
승인된 계획, 브리핑 링크, /goal 문장
/logbook:debrief
PR 직후

기준별 검증 증거와 독립 리뷰 결과로 디브리핑 HTML을 만들어 PR과 이슈에 링크합니다. 리뷰어는 Claude Code에서 Sonnet(medium effort)으로 돌고, 다른 하네스에서는 세션 모델을 씁니다. 끝나면 재리뷰가 필요한지 판정해 머지·재리뷰·남은 지적 고치기·PR 열어두기 중 권장안을 이유와 함께 제시합니다.

예
/logbook:debrief · /logbook:debrief 57
결과
증거 표, 리뷰 포인트, 디브리핑 링크, PR 표식

AGENTS.md 규칙이 있어서 스킬 이름을 부르지 않아도 에이전트가 같은 흐름을 따릅니다. 스킬은 단계를 직접 지정하고 싶을 때 씁니다.

브리핑과 디브리핑에는 주요 로직 흐름도와 ERD 변화(바뀐 엔티티만, 없으면 "ERD 변화 없음" 한 줄)가 반드시 들어갑니다. 나머지 도식은 숫자 타일·전후 트랙·카드·SVG 같은 자유 도식으로 그립니다(templates/diagram-kit.md).

05 / 09hook

hook 두 개가 흐름을 확실하게 받칩니다

plan-preview · 플랜 승인 직전과 직후

브리핑 없는 플랜을 되돌리고, 있는 플랜은 브라우저로 엽니다

  • 플랜에 <!-- brief:begin --> 줄이 없거나, 주요 로직 흐름도나 ERD 변화가 빠지면 플랜을 되돌리고 무엇이 빠졌는지 알려줍니다.
  • 블록이 있으면 .logbook/briefs/plan-preview.html을 만들어 엽니다. 승인은 평소처럼 터미널에서 합니다.
  • 승인 직후에는 코드보다 브리핑 게시와 이슈 링크를 먼저 하라고 알립니다.
  • 작은 수정은 플랜에 <!-- brief:skip -->, 브라우저를 열지 않으려면 LOGBOOK_NO_OPEN=1.
debrief-gate · 턴이 끝날 때

PR에 디브리핑이 없으면 한 번 막습니다

  • 현재 브랜치의 열린 PR 본문에 <!-- logbook:debrief -->가 없으면 턴 종료를 막고 /logbook:debrief를 안내합니다.
  • 기본 브랜치, PR 없음, 병합된 PR, gh 오류, 이미 확인한 커밋은 그대로 통과합니다.
  • 연속으로는 한 번만 막습니다. 무한 반복은 일어나지 않습니다.
06 / 09/mission과 /goal

무인 실행은 /logbook:mission으로 계획하고 /goal로 맡깁니다

  1. /logbook:mission <목표 또는 #이슈>를 실행합니다. 플랜 모드로 들어가 조사하고, 애매한 점만 묻습니다.

  2. 플랜 승인 화면이 뜨면 브라우저의 브리핑을 확인하고 승인합니다.

  3. 이슈, 상세 문서, 작업 브랜치, 브리핑 링크가 준비되고 /goal 문장이 코드 블록으로 나옵니다.

  4. 저장소에서 새 세션을 열어 /goal …을 붙여 넣습니다. 이것이 착수 승인입니다.

  5. 끝나면 PR과 디브리핑 링크가 이슈에 붙습니다. 머지는 사람이 합니다.

/goal 이슈 owner/repo#42를 완료한다. 브랜치 feat/42-rate-limit에 있는 docs/plans/42-rate-limit.md의 계획대로 구현하고 PR을 연다.
완료 조건. 항목마다 확인한 명령과 출력을 대화에 그대로 보인다.
1. `pnpm test`가 종료 코드 0이다.
2. PR 본문에 Closes #42, 수용 기준 체크리스트와 증거, 디브리핑 링크, <!-- logbook:debrief -->가 있다.
지킬 것: main에 직접 커밋하지 않는다. 테스트를 약화하지 않는다.
매 턴 끝에 남은 조건 번호를 적는다. 40턴 안에 끝나지 않으면 멈추고 보고한다.
  • /goal의 평가 모델은 대화만 읽습니다. 조건마다 명령과 출력을 대화에 남기게 합니다.
  • 목표 문장은 4,000자까지입니다. 자세한 내용은 상세 문서에 두고 문장에는 경로만 적습니다.
  • 무인으로 돌리려면 auto 모드에서 실행합니다. Codex의 /goal에도 같은 문장을 쓸 수 있습니다.

09 / 09문제 해결

자주 막히는 곳은 여섯 가지이고, 대부분 설정 한 줄로 풀립니다

규칙이 적용되지 않는 것 같습니다작업 디렉터리 위쪽 어딘가에 다른 CLAUDE.md가 있으면 Claude Code는 AGENTS.md를 읽지 않습니다. 프로젝트에 @AGENTS.md 한 줄짜리 CLAUDE.md가 있는지 확인하고, 없으면 /logbook:rulebook을 다시 실행합니다.
gh 명령이 다른 계정으로 실행됩니다/logbook:rulebook이 gh 계정을 AGENTS.md 트래커 줄에 적습니다. 스킬과 hook은 GH_TOKEN="$(gh auth token --user <계정>)"으로 그 계정을 씁니다.
브리핑 링크를 만들 수 없습니다Artifact는 claude.ai에 로그인하고 Anthropic API로 연결된 세션에서만 게시됩니다. 게시할 수 없으면 .logbook/briefs/의 로컬 파일 경로를 링크로 씁니다.
플랜을 승인할 때 브라우저가 열리지 않습니다LOGBOOK_NO_OPEN이 설정됐는지, 플랜에 <!-- brief:begin -->가 단독 줄로 있는지 확인합니다. 미리보기 파일은 .logbook/briefs/plan-preview.html입니다.
턴이 끝나지 않고 계속 돌아옵니다열린 PR 본문에 <!-- logbook:debrief -->가 있어야 통과합니다. /logbook:debrief를 실행하거나, 작은 수정이면 증거 목록과 표식만 PR 본문에 넣습니다.
Codex에서 스킬이 보이지 않습니다codex plugin list로 설치 상태를 보고 새 세션을 엽니다. hook은 /hooks에서 신뢰 등록해야 실행됩니다.
